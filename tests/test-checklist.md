# Чек-лист ручного тестирования

Проводить тесты только на копиях файлов. Отмечать результат и версию Office/Windows.

## Статический валидатор

- [ ] Валидатор завершается успешно на актуальном репозитории и перечисляет количество найденных модулей и процедур.
- [ ] Если обязательную точку входа временно сделать `Private Sub` или переименовать, валидатор сообщает об ошибке; тестовую поломку не сохранять в основной ветке.
- [ ] Если имя макроса кнопки панели не соответствует существующей `Public Sub`, валидатор сообщает об ошибке; после теста восстановить исходный код.

## SharePoint и синхронизированные папки

- [ ] Для адреса `http://stksps01:55555/SD/Совместное редактирование/НТУ/Отчет НТУ за 3 квартал 2026/НТУ приложения` проверить запись в журнале ожидаемого WebDAV-пути `\\stksps01@55555\DavWWWRoot\SD\Совместное редактирование\НТУ\Отчет НТУ за 3 квартал 2026\НТУ приложения`; отдельно проверить открытие этого пути в Проводнике Windows под той же учётной записью.
- [ ] Проверить URL с UTF-8-кодированными кириллическими символами и пробелами (`%D0...`, `%20`): после преобразования путь должен содержать читаемые символы и пробелы.
- [ ] Проверить адреса `http://сервер`, `http://сервер?параметр=значение` и `https://сервер#раздел` без завершающего `/`: параметры и фрагменты не должны попадать в имя сервера WebDAV.
- [ ] Проверить адреса с путём и параметрами (`http://сервер/SD/папка?параметр=значение#раздел`): в WebDAV-путь должны попасть только сервер и путь до `?` или `#`.
- [ ] Проверить HTTP-адрес с нестандартным портом, например `http://сервер:8080/папка`: ожидаемый префикс WebDAV-пути — `\\сервер@8080\DavWWWRoot\папка`.
- [ ] Проверить HTTPS-адрес с нестандартным портом, например `https://сервер:8443/папка`: ожидаемый префикс WebDAV-пути — `\\сервер@SSL@8443\DavWWWRoot\папка`.
- [ ] Проверить явные стандартные порты `http://сервер:80/папка` и `https://сервер:443/папка`: `@80` и `@443` не должны добавляться в имя WebDAV-сервера; для HTTPS должен сохраняться суффикс `@SSL`.
- [ ] Проверить допустимые граничные порты `http://сервер:1/папка` и `http://сервер:65535/папка`: они должны преобразовываться с соответствующим суффиксом порта; `0` и `65536` должны отклоняться.
- [ ] Проверить некорректные порты `http://сервер:abc/папка`, `http://сервер:65536/папка`, `http://сервер:0/папка`, `http://сервер:-1/папка`, `http://сервер:80.5/папка` и `http://сервер:/папка`: макрос должен показать понятную ошибку до обращения к файловой системе.
- [ ] Проверить порт с ведущими нулями `http://сервер:00080/папка`: после числовой нормализации стандартный порт 80 не должен добавляться к имени WebDAV-сервера.
- [ ] При вводе некорректного адреса проверить, что обработка прекращается до создания резервной копии и изменения целевого листа; в журнале должна быть причина ошибки, а ложное сообщение об удалении нового листа не должно появляться.
- [ ] Адреса IPv6 в квадратных скобках (`http://[2001:db8::1]:8080/папка`, `https://[2001:db8::1]:8443/папка`) и адреса с несколькими двоеточиями должны отклоняться, а не превращаться в некорректный WebDAV-путь. Совместимость IPv6 с Windows WebClient и целевым SharePoint не заявляется.
- [ ] Выбрать синхронизированную SharePoint-папку через диалог Windows: в журнале должен остаться локальный путь, без преобразования в `DavWWWRoot`.
- [ ] Если WebDAV-путь не открывается в Проводнике, убедиться, что макрос регистрирует ошибку доступа и не сообщает, что SharePoint успешно прочитан. Повторить проверку через локальную синхронизированную папку.
- [ ] При ошибке чтения WebDAV в журнале отдельно указаны служба WebClient Windows, авторизация и права доступа; для локальной синхронизированной папки эти рекомендации не выводятся.

## Подготовка
- [ ] Создана тестовая папка с несколькими объектами и вложенными папками.
- [ ] Есть Word-отчёт, Word-приложение, PDF-приложение и Excel-приложение.
- [ ] Есть файл, название которого не соответствует шаблону, и файл с кириллицей/пробелами в имени.
- [ ] На листе `data` заполнены тестовые названия приложений, отделы, объекты и ответственные лица.
- [ ] В существующем перечне вручную заполнено несколько значений в столбце H «Раздел».

## Формирование перечня

- [ ] В автономном модуле выбрать папку, имя которой совпадает с именем пользовательского листа без заголовков перечня: пользовательский лист должен остаться без изменений, а новый перечень должен получить уникальное имя.
- [ ] Поместить в исходную папку временный файл Office с префиксом `~$`, скрытый файл и саму книгу с макросом: эти файлы не должны попадать в перечень.
- [ ] Создать вложенную папку глубже `MAX_FOLDER_DEPTH`: макрос должен записать предупреждение о непросмотренной глубине и запросить подтверждение неполного перечня.
- [ ] В автономном модуле вставить SharePoint-адрес длиной 254 символа или больше: макрос должен остановиться до создания резервной копии и изменения листа.

- [ ] Первый запуск через `StartRegisterAutomation` создаёт книгу результата только после обнаружения листа `data` и запускает формирование перечня.
- [ ] Кнопка «Повторно создать перечень» на панели перестраивает текущую книгу результата и не создаёт дополнительную книгу.
- [ ] После повторного построения панель управления остаётся доступной, а значения «Раздел» сохраняются.
- [ ] Если создание панели кнопок завершается ошибкой, сформированный перечень сохраняется, а ошибка панели выводится отдельно.
- [ ] Можно выбрать одну папку.
- [ ] Можно выбрать несколько папок.
- [ ] Папка SharePoint, синхронизированная с Проводником Windows, выбирается и сканируется как обычная папка Windows.
- [ ] Обычный локальный путь Windows после нормализации не меняется.
- [ ] При запуске можно выбрать локальные папки через Проводник или вставить HTTP/HTTPS-адрес SharePoint вручную.
- [ ] Для тестового HTTP-адреса проверяется ожидаемое преобразование в WebDAV UNC-путь; тест подтверждает только преобразование строки, а не доступ к серверу.
- [ ] В URL с процентным кодированием кириллические символы и пробелы декодируются перед преобразованием в WebDAV-путь.
- [ ] Для URL с другим протоколом, пустого адреса и отмены ввода макрос завершает выбор без перестройки листа.
- [ ] Для `http://stksps01:55555/SD/Совместное редактирование/НТУ/Отчет НТУ за 3 квартал 2026/НТУ приложения` ожидаемый путь начинается с `\\stksps01@55555\DavWWWRoot\SD\Совместное редактирование\НТУ\Отчет НТУ за 3 квартал 2026\НТУ приложения` (проверить два начальных обратных слеша и разделитель после `DavWWWRoot`).
- [ ] Если WebDAV недоступен, макрос сообщает путь и ошибку чтения в журнале, не завершаясь раньше времени при определении имени листа.
- [ ] Если пользователь отказывается от формирования неполного перечня после ошибок чтения папок, исходный лист остаётся без изменений, а временная резервная копия удаляется.
- [ ] Для реального SharePoint отдельно проверяются права доступа, поддержка WebDAV и наличие файлов; этот тест выполняется только в среде пользователя.
- [ ] Если одновременно выбраны родительская папка и вложенная в неё папка, каждый файл попадает в перечень только один раз.
- [ ] Отмена диалога выбора папок завершает операцию без повреждения книги.
- [ ] Объект определяется только из шести значений: `СМТ`, `АМТ`, `КТ`, `КЗТ`, `Саратов`, `НТУ`.
- [ ] При поиске объекта проверяются папки от папки файла вверх до выбранного корня включительно; ближайшее совпадение внутри выбранного дерева имеет приоритет.
- [ ] Если код объекта есть только в папке выше выбранного корня, он игнорируется; объект определяется по имени файла, если код есть в имени, иначе ячейка остаётся пустой.
- [ ] Если кода объекта нет в выбранной папке и её вложенных папках, объект определяется по имени файла; если и в имени файла кода нет, ячейка остаётся пустой.
- [ ] Совпадение с кодом объекта внутри другого слова не считается; буква `Ё/ё` учитывается как часть кириллического слова.
- [ ] Если объект не найден ни в папках, ни в имени файла, столбец «Объект» остаётся пустым.
- [ ] В столбце «Объект» отражается найденный объект, а не произвольное имя выбранной папки.
- [ ] Соблюдается ограничение глубины обхода папок.
- [ ] При большом количестве файлов статус обновляется в процессе обхода, а Ctrl+Break обрабатывается между файлами.
- [ ] Нажать Ctrl+Break при чтении гиперссылки и сохранении значений H «Раздел»; отмена должна дойти до основного обработчика, а существующий лист — восстановиться.
- [ ] Нажать Ctrl+Break во время определения имени папки SharePoint и проверки наличия листа; отмена не должна превращаться в обычное предупреждение или продолжать построение.
- [ ] Отчёты распознаются по согласованному правилу.
- [ ] Основные отчёты распознаются с префиксами «Отчет_», «Отчёт_», «Отчет » и «Отчёт »; префикс не попадает в поле «Наименование».
- [ ] Номера приложений и наименования корректно извлекаются из тестовых имён.
- [ ] Файлы DOCM включаются в перечень так же, как DOC и DOCX.
- [ ] Номер приложения извлекается для форм «Приложение», «Приложения», «Приложению», «Приложением», «Приложении», «Приложений» и сокращения «Прил».
- [ ] Дубликаты с ведущими нулями распознаются как одинаковые (например, 01 и 1), а буквенные суффиксы различаются (1А и 1Б).
- [ ] Проверены имена `СМТ_Приложение № 1_Земельные участки.pdf`, `АМТ_Приложение номер 15_Фототчет.pdf`, `КТ_Прил. № 12_Схема.pdf`, `КТ_Прил 12_Схема.pdf` и имя без номера приложения.
- [ ] В номере с буквенным суффиксом (например, `15А`) буква не теряется.
- [ ] Файлы группируются и сортируются в ожидаемом порядке.
- [ ] Ссылки открывают правильные файлы.
- [ ] Переименование корректно читает пути гиперссылок в формате `file:///...`, с `%20` вместо пробелов и с прямыми слешами.
- [ ] Подсчёт страниц корректно читает пути гиперссылок в формате `file:///...`, с `%20` вместо пробелов и с прямыми слешами.
- [ ] При наличии строки с неподдерживаемым форматом в итоговом сообщении она учитывается в числе проблем, а в столбце J показывается «Неподдерживаемый формат».
- [ ] Форматирование соответствует требованиям; FreezePanes не используются.
- [ ] Значения «Раздел» сохраняются при повторном построении по пути файла.
- [ ] Сохранение «Раздела» работает, если гиперссылка хранит путь как `file:///...` или использует `%20` для пробелов.
- [ ] В автономном модуле проверить сохранение «Раздела» после сохранения книги, когда адрес гиперссылки содержит относительный путь (`Подпапка\файл.pdf` или `..\Документы\файл.pdf`): путь разрешается относительно «Базы гиперссылок», а при её отсутствии — относительно папки книги.
- [ ] Проверить, что абсолютные пути диска и UNC, HTTP/HTTPS и `file:///...` не дополняются папкой книги при сохранении «Раздела».
- [ ] Файл с названием, содержащим фразу «2 кв 2026» как часть более длинного названия, не получает тире автоматически в столбце «Отдел».
- [ ] Имя «Отчет 2 кв 2026» без подчёркивания и имя «Реестр_рисков» с подчёркиванием не получают тире автоматически в столбце «Отдел».
- [ ] Отдел и ответственное лицо подставляются из листа `data`.
- [ ] Только для файлов с точными базовыми именами «Отчет_2 кв 2026» и «Реестр рисков» в отделе отображается «—».
- [ ] Недоступный/повреждённый файл не прекращает всю обработку без понятного сообщения.

## Word: страницы и упоминания
- [ ] Подсчёт страниц проверен на документе с несколькими страницами.
- [ ] Поиск находит несколько упоминаний одного приложения.
- [ ] Поиск находит сокращённые записи «Прил. № 12» и «Прил № 12» наряду с полным словом «Приложение».
- [ ] Найденные страницы соответствуют расположению упоминаний в Word.
- [ ] Уровень структуры соответствует уровню абзаца Word для документов с несколькими уровнями заголовков.
- [ ] PDF-страницы подсчитываются только при наличии совместимого Adobe Acrobat Pro/Standard; без него появляется понятное сообщение.
- [ ] Таблицы и абзацы внутри таблиц Word проверены отдельно, так как структура отчёта может влиять на полноту поиска.
- [ ] Отсутствие совпадений обрабатывается без ошибки.

## Word: подписи и нумерация таблиц
- [ ] Предварительный отчёт на листе «Проверка таблиц» содержит все ожидаемые таблицы основного документа.
- [ ] Существующее поле `SEQ Таблица` распознаётся и не получает вторую подпись.
- [ ] Существующее поле `SEQ Таблица` распознаётся, если между подписью и таблицей есть одна или несколько пустых строк (в пределах четырёх проверяемых абзацев).
- [ ] Поле `SEQ Таблица` внутри обычного абзаца, который не начинается с подписи «Таблица», не должно засчитываться как подпись проверяемой таблицы.
- [ ] Существующая текстовая подпись «Таблица …» без поля `SEQ` не должна автоматически дублироваться; в отчёте отмечается для ручной проверки.
- [ ] Таблица без поля `SEQ Таблица` попадает в предварительный отчёт.
- [ ] Отказ от подтверждения не изменяет Word-документ.
- [ ] После подтверждения над таблицей добавляется подпись с автоматическим полем Word `SEQ`.
- [ ] После обновления полей номера таблиц идут последовательно, а ссылки/содержание обновлены там, где применимо.
- [ ] Проверены таблицы внутри ячеек, вложенные таблицы, подписи с пустыми строками и таблицы около разрывов страниц.
- [ ] На копии отчёта проверить последовательность «таблица A — подпись с SEQ фактически под A — таблица B»: убедиться, что подпись не засчитывается ошибочно как подпись над B; если сопоставление неоднозначно, не запускать автонумерацию без ручной проверки.
- [ ] Исходный документ до теста скопирован; изменения проверены визуально.

## Word: маркированные списки
- [ ] Группа из двух и более абзацев с ручными дефисами/тире попадает в лист «Проверка списков».
- [ ] Группы с маркерами `•`, `●`, `○`, `◦`, `▪`, `▫`, `·` и `*` также распознаются, если после маркера есть пробел или табуляция.
- [ ] Обычный текст с одиночным тире не преобразуется.
- [ ] Уже оформленный нативный список Word не меняется.
- [ ] Отказ от подтверждения оставляет документ без изменений.
- [ ] После подтверждения ручные маркеры удаляются, применяется настоящий маркированный список Word.
- [ ] Проверены группы в начале/конце страницы, разные отступы, табуляции, пустые строки и абзацы в таблицах.
- [ ] После преобразования визуально проверены уровни списка, переносы и отступы.
- [ ] При отмене посреди операции документ проверен на частично внесённые изменения.

## Переименование
- [ ] До изменения показывается список старых и новых имён.
- [ ] Отказ от подтверждения оставляет файлы без изменений.
- [ ] Расширение сохраняется.
- [ ] Недопустимые символы и пустые обязательные поля обрабатываются.
- [ ] Дубликаты целевых имён обнаруживаются до операции.
- [ ] Если один и тот же исходный путь встречается в нескольких строках перечня, в план переименования попадает только первая корректная строка-кандидат; повторные корректные строки отмечаются в списке пропусков, а некорректная первая строка не блокирует последующую корректную.
- [ ] Если имя файла уже соответствует полям первой корректной строки, переименование не выполняется, но последующая строка с тем же исходным путём не должна переименовать этот файл по другим полям.
- [ ] Существующий файл с целевым именем не перезаписывается.
- [ ] Журнал содержит старый путь, новое имя, новый путь и статус каждой попытки.
- [ ] RollbackLastRenameBatch возвращает имена только последнего пакета на копиях файлов и обновляет гиперссылки в листе перечня.
- [ ] Повторный откат не затрагивает предыдущие пакеты переименования.
- [ ] После полного отката последнего пакета повторный запуск отката выбирает предыдущий пакет, если в нём ещё остались переименованные файлы.
- [ ] Два запуска в одну секунду получают разные ID пакетов.
- [ ] Старый журнал без ID пакета не запускает автоматический массовый откат.
- [ ] Откат пропускает файлы, если исходное имя уже занято.
- [ ] Искусственно вызвать ошибку после нескольких успешных переименований; автоматический откат должен обрабатывать выполненные операции в обратном порядке, восстанавливать ссылки и отмечать результат каждой операции в журнале.
