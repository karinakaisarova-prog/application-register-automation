# Первый безопасный запуск

Эта инструкция рассчитана на установщик: вручную импортировать девять модулей не нужно.

## 1. Создать рабочую копию книги

1. Скачайте архив проекта: на странице GitHub нажмите **Code → Download ZIP** (элементы сайта могут отображаться на английском), затем распакуйте архив.
2. Откройте папку `tools` и запустите `Установить_книгу_Excel.cmd`.
3. В первом диалоге выберите свою существующую Excel-книгу, где уже есть лист `data`.
4. Во втором диалоге укажите имя и папку для новой копии `.xlsm`. Исходный файл не перезаписывается.
5. Установщик сохранит листы исходной книги, включая `data`, и добавит VBA-модули. Перечень будет создаваться в этой же новой копии.

Если Excel блокирует программное добавление модулей, установщик сообщит об этом. Не меняйте настройки безопасности, если не уверены, что понимаете их последствия.

## 2. Только скомпилировать — пока ничего не запускать

1. Откройте созданную `.xlsm`-копию в настольном Excel для Windows.
2. Нажмите **Alt+F11**, чтобы открыть редактор Visual Basic.
3. Выполните команду проверки компиляции проекта. В английской версии редактора это **Debug → Compile VBAProject**; в русской версии название команды может быть переведено.
4. Если компиляция прошла без сообщения об ошибке, это подтверждает только успешную компиляцию в данной среде, но не гарантирует, что макросы правильно работают с файлами.
5. Если появилась ошибка, остановитесь. Запишите полный текст ошибки и имя выделенной строки/процедуры или пришлите скриншот. Не исправляйте строку наугад и пока не запускайте макросы.

## 3. Проверить справочник

Убедитесь, что в созданной копии есть лист с точным именем `data`:
- столбец A — наименование приложения;
- столбец B — отдел;
- C1:F1 — названия объектов;
- C:F — ответственные лица для соответствующих объектов.

Установщик копирует исходную книгу и не должен менять её. Работайте дальше в созданной копии.

## 4. После успешной компиляции

1. Запустите `StartRegisterAutomation` через **Alt+F8**.
2. Выберите копию папок с несколькими тестовыми файлами, не оригинальные рабочие папки.
3. Проверьте созданный лист перечня, заголовки и ссылки на файлы.

Пока не запускайте переименование, откат переименования, нумерацию таблиц и исправление маркированных списков на рабочих документах. Эти функции требуют отдельной проверки на копиях.

## Что сообщить после этапа 1

- **«Компиляция прошла»** — перейдём к безопасному тесту на копиях.
- **«Ошибка компиляции: …»** — пришлите полный текст ошибки и выделенную строку/процедуру или скриншот.

Не нужно проверять все макросы вручную по отдельности.
