# Первый запуск и безопасная проверка

Цель первого этапа — проверить, что VBA-проект компилируется в настольном Excel. На этом этапе макросы не запускаем и файлы не переименовываем.

## 1. Скачать проект

Откройте репозиторий: https://github.com/karinakaisarova-prog/application-register-automation

Нажмите **Code → Download ZIP** и распакуйте архив в обычную папку на компьютере. Не открывайте проект в Excel Online: VBA проверяется в настольном Excel для Windows.

## 2. Подготовить книгу с макросами

1. Откройте настольный Excel и создайте пустую книгу.
2. Сохраните её как **Книга Excel с поддержкой макросов (*.xlsm)**, например `ApplicationRegisterTest.xlsm`.
3. Нажмите **Alt+F11**, чтобы открыть редактор Visual Basic.
4. В редакторе выберите **File → Import File…** и импортируйте модули из папки `src/vba` по одному: все девять файлов `.bas`.
5. Если эти модули уже есть в проекте, не импортируйте их повторно: это может создать дубликаты.

## 3. Только скомпилировать — пока ничего не запускать

1. В редакторе Visual Basic выберите **Debug → Compile VBAProject**. В некоторых версиях команда может называться «Compile» с именем проекта.
2. Если команда недоступна, сначала выберите проект книги с макросами в окне Project Explorer.
3. Если компиляция прошла без сообщения об ошибке, это означает только, что проверенная часть VBA синтаксически компилируется в вашей версии Office. Это ещё не подтверждает работу макросов на реальных файлах.
4. Если появляется ошибка, остановитесь. Запишите полный текст ошибки и имя выделенной строки/процедуры либо пришлите скриншот. Не исправляйте строку наугад и пока не запускайте макросы.

## 4. Подготовить данные перед первым запуском

Точка входа для старта — `StartRegisterAutomation`. Она ожидает лист `data` в книге с макросами либо предлагает выбрать книгу-источник с таким листом.

Структура листа `data`:
- столбец A — наименование приложения;
- столбец B — отдел;
- C1:F1 — названия объектов;
- C:F — ответственные лица для соответствующих объектов.

Используйте ваши реальные справочные данные. Не заполняйте справочник вымышленными значениями. Если листа `data` пока нет, ограничьтесь компиляцией и не запускайте `StartRegisterAutomation`.

## 5. После успешной компиляции

Следующий этап — тест на копиях нескольких файлов в отдельной тестовой папке. Сначала проверяем только построение перечня и ссылки. Не запускайте на исходных документах:
- переименование файлов;
- откат переименования;
- нумерацию таблиц;
- исправление маркированных списков.

Эти операции требуют отдельной проверки на копиях. Возможности отката отличаются между макросами; не следует считать, что любое изменение автоматически обратимо.

## Что сообщить после этапа 1

Достаточно одного из двух ответов:

- **«Компиляция прошла»** — тогда можно переходить к подготовке тестовой папки и первому безопасному запуску.
- **«Ошибка компиляции: …»** — пришлите полный текст ошибки и выделенную строку/процедуру или скриншот.

Не нужно проверять все макросы вручную по отдельности.
