# Техническое задание: автоматизация перечня приложений

## 1. Цель

Создать набор макросов VBA для настольного Excel под Windows, который формирует перечень приложений к основным отчётам, помогает находить упоминания приложений в Word-отчёте и поддерживает безопасное переименование файлов.

## 2. Основной перечень

### 2.1. Выбор папок и поиск файлов
- Пользователь выбирает одну или несколько исходных папок через диалог выбора папок.
- Макрос обрабатывает выбранные папки и вложенные папки с ограничением глубины, согласованным в настройках проекта (целевое значение — 3 уровня).
- Столбец «Объект» определяется только по одному из шести допустимых значений: `СМТ`, `АМТ`, `КТ`, `КЗТ`, `Саратов`, `НТУ`.
- Сначала проверяются имена папок от папки файла вверх до выбранной исходной папки включительно. Родительские папки выше выбранной исходной папки не учитываются. Если в этой цепочке совпадение не найдено, проверяется имя файла.
- Совпадение должно быть отдельным кодом/словом, а не частью другого слова. Если ни в папках, ни в имени файла объект не найден, ячейка «Объект» остаётся пустой; случайное имя папки не подставляется.
- Файлы основного отчёта распознаются по принятому префиксу «Отчет_»; правила распознавания должны быть централизованы и документированы.
- Форматы приложений: Word, PDF и Excel.

### 2.2. Таблица
Строка 1 — объединённый заголовок «Перечень приложений». Заголовки таблицы расположены во второй строке, данные начинаются с третьей.

Столбцы A:J:
1. № п/п
2. Объект
3. № Прил.
4. Наименование
5. Отдел
6. Ответственное лицо
7. Ссылка на файл
8. Раздел
9. Стр. отчёта
10. Кол-во страниц

Временные служебные столбцы, если необходимы для сортировки, не должны мешать пользователю и должны корректно удаляться/скрываться после обработки.

### 2.3. Форматирование
- Шрифт Times New Roman.
- Заголовки таблицы: светло-зелёная заливка, тёмный текст, курсив.
- Границы ячеек и компактные размеры строк/столбцов.
- Не использовать FreezePanes.
- В столбце ссылки отображать понятный текст или значок открытия файла, а не длинный путь как видимый текст.

### 2.4. Сохранение ручных данных и справочник
- Столбец H «Раздел» заполняется вручную.
- При повторном построении перечня значения «Раздел» сохраняются по нормализованному пути файла, если соответствующий файл по-прежнему присутствует. При сопоставлении учитываются варианты адреса гиперссылки `file:///...`, различия `/` и `\\`, а также URL-кодирование пробелов `%20`.
- Лист справочника должен называться строго `data` (нижний регистр).
- На листе `data`: A — наименование приложения/отчёта; B — отдел; C1:F1 — названия объектов; C:F — данные ответственных лиц.
- Только для файлов с точными базовыми именами `Отчет_2 кв 2026` и `Реестр рисков` в столбце «Отдел» отображать тире «—». Совпадение произвольного более длинного названия, в котором лишь встречается фраза «2 кв 2026», не считается специальным файлом.

## 3. Поиск упоминаний в Word-отчёте
- Отдельный макрос сканирует основной отчёт Word (.doc/.docx).
- Сохраняет все найденные упоминания приложений, а не только первое совпадение.
- Для каждого найденного приложения определяет страницу отчёта и наиболее глубокий применимый уровень структуры/нумерации, если эти уровни присутствуют в документе.
- Поиск упоминаний и подсчёт страниц должны быть отдельными процедурами от построения перечня.

## 4. Переименование файлов
- Переименование запускается отдельно от формирования перечня.
- Пользователь редактирует существующие поля исходной таблицы; не требуется создавать альтернативную таблицу с дублирующими полями.
- Целевой шаблон имени: `ОБЪЕКТ_Приложение № НОМЕР_НАИМЕНОВАНИЕ.РАСШИРЕНИЕ`.
- Пример: `АМТ_Приложение № 15_Фототчет.pdf`.
- Сохранять исходное расширение файла.
- Перед переименованием сформировать предварительный список старых и новых имён и запросить подтверждение.
- Проверять пустые значения, недопустимые символы, дубликаты и существующие файлы с целевыми именами.
- Сохранять журнал старого и нового имени, достаточный для ручного отката операции.

## 5. Подтверждение, прерывание, резервирование и откат

Эти требования обязательны для каждого макроса проекта, а не только для переименования.

### 5.1. Прерывание
- Длительную операцию можно прервать пользователем через Ctrl+Break/Esc там, где это поддерживает Excel/VBA; макрос должен регулярно передавать управление через `DoEvents`.
- Для операций с Word прерывание должно обрабатываться и в Excel-коде, управляющем Word COM. Нельзя проглатывать ошибку отмены в локальном обработчике ошибок.
- После прерывания макрос прекращает новые изменения, закрывает открытые объекты Word/файлов в безопасном режиме и восстанавливает настройки Excel, изменённые при запуске (`ScreenUpdating`, `EnableEvents`, `DisplayAlerts`, `Calculation`, `StatusBar`, `EnableCancelKey` и другие, если они менялись).
- Пользователь получает понятное сообщение: что успело выполниться, что не завершено и нужно ли восстановление.

### 5.2. Откат и защита исходных данных
- Любой макрос, который меняет данные или документы, должен иметь предусмотренный способ отменить свои изменения.
- До изменения книги/документа/файлов создаётся точка восстановления: резервная копия документа/файла либо сохранённый снимок затрагиваемых данных. Для массового изменения файлов ведётся журнал операции с уникальным ID, исходным и новым состоянием.
- Для Word-макросов, меняющих содержимое, исходный документ должен быть сохранён в резервную копию до первой правки. Откат должен восстанавливать исходный документ, а не просто закрывать его без сохранения после частично выполненных действий.
- Для перестроения листа перечня сохраняются исходные значения и структура листа до очистки/перезаписи; при ошибке или отмене восстанавливается предыдущее состояние листа.
- Для `data_full` откат должен восстанавливать прежнее содержимое листа, если сборка не завершилась.
- Для операций переименования используется журнал пакета и отдельная процедура отката. Откат не должен перезаписывать занятые имена и обязан фиксировать пропущенные элементы.
- После успешного выполнения пользователь может запустить отдельную процедуру отмены последней операции для тех действий, где это предусмотрено. Необратимые операции без сохранённой точки восстановления запрещены.
- Перед массовым изменением документа сначала формируется предварительный отчёт, затем запрашивается подтверждение. Отказ не должен менять исходные данные.
- Журнал и статус отображаются в Excel; отдельный внешний лог-файл не создаётся без отдельного согласования.

### 5.3. Обработка ошибок
- Ошибка одного файла не должна молча уничтожать результаты обработки других файлов.
- Все процедуры, меняющие состояние Excel, обязаны иметь единый шаблон очистки/восстановления и обработчик отмены.
- В сообщении об ошибке указывается этап операции, файл/путь (если известен), описание ошибки и статус отката.
- Нельзя сообщать об успешном откате, если восстановление не подтверждено.


## 6. Критерии приёмки
- Повторное формирование перечня не теряет вручную заполненные значения «Раздел».
- Объекты и номера приложений извлекаются согласно согласованным правилам именования.
- Сортировка группирует основные отчёты и приложения по объекту в согласованном порядке.
- Ссылки открывают соответствующие файлы.
- Ошибки доступа/формата одного файла не приводят к потере уже собранных данных.
- Переименование не перезаписывает существующие файлы и запрашивает подтверждение.
- После отмены/ошибки Excel возвращается в рабочее состояние.\n- Каждый изменяющий макрос имеет подтверждение перед правкой, точку восстановления, безопасное прерывание и проверяемый откат.
- Проверка проводится на копиях исходных документов.

## 7. Не входящие в текущую реализацию
- Отдельное самостоятельное приложение вне Excel — возможный будущий этап; текущая реализация выполняется в VBA внутри книги Excel.
- Автоматическое исправление содержимого Word/PDF/Excel не считается реализованным, пока отдельный код и тесты не добавлены.
