# Дополнительный аудит и план проверок

Документ дополняет docs/current-state.md результатами статического просмотра исходного кода. Он не означает, что код запускался или что перечисленные сценарии уже пройдены.

## 1. Переименование и откат — src/vba/modRenameFiles.bas

### Наблюдения по коду

- В ветке успешного переименования обновление гиперссылки выполняется под On Error Resume Next, после чего журнал и счётчик всё равно фиксируют успех. Следовательно, файл может получить новое имя, а ссылка в перечне остаться старой или не создаться.
- При ручном откате строка журнала может получить статус «Откатан» до подтверждения, что новая гиперссылка действительно создана.
- В обработчике прерывания ошибки восстановления ссылок и журнала могут подавляться. Поэтому фактическое состояние книги может отличаться от текста журнала.
- В ветке, где файл уже найден по старому пути, статус может быть отмечен как «Откатан» без проверки/восстановления ссылки в перечне.
- Нормализация пути обрабатывает file:/// , %20 и разделители, но не выполняет полное декодирование URL. Пути с другими закодированными символами требуют отдельного теста.
- Очистка имени заменяет запрещённые символы, но не гарантирует устранение всех проблемных имён Windows, в том числе завершающих точек/пробелов и зарезервированных имён устройств.

### Требуемое поведение перед выпуском

1. Разделить операции переименования файла, проверки фактического пути, обновления ссылки и записи журнала.
2. Считать операцию успешной только после проверки фактического существования файла по новому пути и корректности адреса гиперссылки.
3. Если обновить ссылку не удалось, попытаться вернуть исходное имя и исходную ссылку; отдельно записать результат каждого действия.
4. При частичном восстановлении не показывать сообщение о полном откате. Вывести перечень файлов, ссылок и строк журнала, которые требуют ручной проверки.
5. Перед ручным откатом проверить оба пути и не перезаписывать существующие файлы.
6. Проверить нормализацию локальных путей и гиперссылок с пробелами, символами кириллицы, #, %, скобками и URL-кодированием.
7. Не считать журнал абсолютной гарантией транзакционности: сбой Excel может помешать записи журнала после файловой операции.

## 2. Нумерация таблиц — src/vba/modTableNumbering.bas

### Наблюдения по коду

- EnsureTableCaptionLabel подавляет ошибки создания/получения метки подписи. Последующая вставка подписи может завершиться другой ошибкой или неполным результатом.
- UpdateAllStoryFields подавляет ошибки обновления полей. Сам факт возврата из процедуры не подтверждает, что все поля обновлены.
- Для списка таблиц используется wdDoc.Tables; охват вложенных таблиц, колонтитулов, текстовых блоков и других областей не подтверждён запуском.
- Поиск поля SEQ рядом с таблицей основан на предшествующих абзацах. Нестандартная структура подписи может привести к неверной классификации.
- В лист предварительного отчёта нужно писать через временный лист и заменять предыдущий отчёт только после успешного завершения сканирования. Иначе ошибка сканирования может оставить неполный результат вместо предыдущего.

### Требуемое поведение перед выпуском

1. Не подавлять ошибку создания метки без проверки, что метка действительно доступна.
2. Проверять результат обновления полей и сообщать, если часть полей не обновилась.
3. Сначала сформировать отчёт на временном листе, затем заменить старый лист только после завершения сканирования.
4. Явно определить область поддержки: основные таблицы документа либо все таблицы во всех story ranges. Не заявлять поддержку колонтитулов/текстовых блоков без отдельной реализации и тестов.
5. Проверить, что подпись относится именно к следующей таблице и не дублирует уже существующую пользовательскую подпись.

## 3. Проверка маркированных списков — src/vba/modBulletListAudit.bas

Эвристика преобразует группы из двух и более последовательных абзацев с текстовыми маркерами. Это снижает риск случайного преобразования одиночной фразы, но не доказывает, что каждая найденная группа действительно является списком.

Перед использованием на рабочих документах проверить:
- многострочные элементы и переносы строк;
- пустые абзацы внутри списка;
- сочетание маркеров разных видов;
- абзацы с тире, которые являются обычным текстом;
- сохранение жирного/курсивного форматирования, гиперссылок и отступов;
- поведение при отмене после обработки части документа.

## 4. Приоритетный ручной чек-лист

Все проверки выполнять только на копиях книги и документов.

### Переименование
- [ ] Успешное переименование: файл существует по новому пути, ссылка открывает именно его, журнал соответствует факту.
- [ ] Сбой создания гиперссылки: успех не фиксируется без проверки; результат попытки восстановления виден пользователю.
- [ ] Целевой файл уже существует: исходный файл не изменён.
- [ ] Исходный файл отсутствует: операция пропущена с ясной причиной.
- [ ] Ctrl+Break до первой операции, между двумя операциями и во время отката.
- [ ] После прерывания сравнить фактические файлы, гиперссылки и журнал.
- [ ] Повторный запуск отката не должен ошибочно помечать непроверенные действия успешными.
- [ ] Пути с пробелами, кириллицей, #, %, скобками и несколькими точками в имени.

### Нумерация таблиц
- [ ] Документ без таблиц.
- [ ] Все таблицы уже имеют корректные поля SEQ.
- [ ] Таблица без подписи.
- [ ] Существующая подпись без поля SEQ.
- [ ] Пустые абзацы между подписью и таблицей.
- [ ] Вложенная таблица.
- [ ] Таблица в колонтитуле и в текстовом блоке — либо корректно поддерживается, либо явно обозначена как вне области поддержки.
- [ ] Ошибка обновления полей и отмена до/после внесения изменений.
- [ ] После сбоя сравнить исходный файл с резервной копией и проверить, что журнал не утверждает об успешном обновлении без подтверждения.

### Маркированные списки
- [ ] Группа из двух и более реальных элементов с дефисом.
- [ ] Одиночный абзац с тире в обычном тексте.
- [ ] Группа с маркером •, * и разными видами тире.
- [ ] Список с пустой строкой или обычным абзацем между элементами.
- [ ] Сохранение форматирования и гиперссылок после преобразования.
- [ ] Отмена в ходе изменения и проверка резервной копии.

## 5. Критерий готовности

Проект нельзя считать готовым к рабочему использованию, пока:
- VBA-модули не импортированы и не скомпилированы в целевой книге;
- каждый сценарий чек-листа не проверен в настольных Excel и Word;
- отдельно не проверены реальные файловые пути, гиперссылки, резервные копии и откат;
- пользователь не проверил итоговые документы визуально.

Этот документ фиксирует статические выводы и план проверок. Он не является отчётом о пройденных тестах и не заменяет проверку выполнения макросов.
