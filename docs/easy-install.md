# Установка макросов в уже существующую рабочую книгу

Установщик Windows `tools/Установить_книгу_Excel.cmd` добавляет девять VBA-модулей **в ту рабочую копию книги, с которой ты уже работаешь**. Он не предлагает создавать ещё одну копию для перечня.

## Как запустить

1. Скачай ZIP-архив репозитория через **Code → Download ZIP** и распакуй его.
2. Закрой выбранную рабочую книгу в Excel, если она открыта.
3. В распакованной папке открой `tools` и запусти `Установить_книгу_Excel.cmd`.
4. В диалоге выбери свою текущую рабочую копию, в которой есть лист с точным именем `data`. Перед установкой рядом автоматически создаётся резервная копия исходного файла; не удаляй её, пока не убедишься, что всё работает.
5. Если файл уже `.xlsm`, установщик добавит модули непосредственно в него. Если файл `.xlsx`, `.xlsb` или `.xls`, Excel создаст рядом файл с тем же именем и расширением `.xlsm`, поскольку обычный формат не может хранить VBA-код. Если такой `.xlsm` уже существует, установщик остановится, чтобы не перезаписать его.
6. После завершения открой рабочую `.xlsm`-книгу, нажми **Alt+F11 → Debug → Compile VBAProject**.
7. Если компиляция выдаст ошибку, остановись и сохрани текст ошибки/скриншот. Не запускай макросы до исправления.

## Что будет в книге

Лист `data` остаётся на месте. Лист перечня, `data_full`, журнал и панель кнопок создаются/используются в этой же рабочей книге. Отдельная книга результата не создаётся.

## Важные ограничения

- Установщик требует Windows, настольный Excel и доступ к объектной модели проектов VBA. Если Excel блокирует доступ, установщик сообщит об этом. Включай разрешение только если доверяешь коду проекта и понимаешь последствия.
- Установщик и исходники ещё не прошли запуск на твоём компьютере. Успешная установка не заменяет компиляцию и проверку на тестовых копиях документов.
- До успешной компиляции не запускай макросы на рабочих документах.
